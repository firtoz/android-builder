# Lifecycle and CI

A preparation creates a new private directory containing exact source manifest, immutable input hashes, resolved public build configuration and a versioned journal. The build ID is independent of its directory name. Preparation runs Git and archive tools locally, never a project lifecycle script. Exported SDK functions hold an exclusive controller lock; a stale lock requires inspecting its recorded process, never automatic removal based on PID alone.

The journal persists allocating before a provider call, then retains the same allocation operation/expiry across reconnects. The Boat adapter uses Jetski's durable provider journal for reconciliation. Uploads can be repeated before launch because the exact destination and bytes are fixed. Launch intent is persisted before sending, and the host fsyncs an exclusive claim before spawning. A missing acknowledgement causes observation, never a second build launch. An interrupted claim/spawn gap may require manual retirement and a deliberately new build.

Output uses bounded byte cursors. Compiler failures remain failures with original logs and stage timings; truncated output is explicitly recorded. An unresponsive or timed-out process can leave its last recorded status running until lease expiry; the controller does not invent completion. A failed build can retire after its failure receipt; uncertain transfers retain the source. Artifact publication verifies bytes before acknowledgement and retirement. A hard-expired host cannot be reconstructed from receipts alone: they contain source and evidence, not remote compiler caches or filesystem checkpoints.

The default maximum execution is50minutes within a one-hour machine lease. Bootstrap/setup/transfer also consume that lease. Shorter custom lifetimes must leave60seconds beyond execution and enough practical setup/transfer time. Cold toolchain installation remains part of each host; prepared images/cache reuse are future work.

For CI, use a trusted checkout, a durable private receipt/log artifact, a protected Boat credential and an explicit per-build allowance. Use `prepare`, review/configure the source boundary, then `run`. Export only the approved APK and sanitized receipts. Do not use untrusted pull-request code with provider credentials or signing keys. Do not put secrets into publicEnvironment, publicInputs, lifecycle scripts or source archives. A separate trusted signing job verifies application ID and the pinned signing certificate. No workflow automatically spends money or signs/publishes by default.

Both self-contained examples are local candidates pending real hosted builds. The native example pairs AGP8.13.2 with Gradle8.13/JDK17/SDK36; [Android compatibility](https://developer.android.com/build/releases/agp-8-13-0-release-notes) documents that line. Its small bootstrap verifies the pinned distribution checksum; it is not a bundled official Gradle wrapper. You may use your existing checked-in wrapper instead. SDK tools and package managers install on the dedicated host only.
